11. Working culture and agent reporting
Assume the team is capable. Give people outcomes, not micromanagement. Use local agents heavily: they read Plane tasks, do authorised work, update Plane regularly, attach evidence, surface blockers, create follow-up tickets. Never "working on it". Prefer evidence: architecture updated, system queried, API tested, repository identified, owner confirmed, stakeholder interviewed, data flow verified, MCP tool demonstrated, capability operating on the wire. If something is claimed to work, verify it. (ChrisJane publishes the detailed reporting convention here under ticket G-03.)
